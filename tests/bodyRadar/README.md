`node --test tests/bodyRadar/*.test.ts` 验证点云数据校验及框选在CSS缩放、反向拖动和超出边界时的像素映射。

`npx vite --config tests/bodyRadar/capture.vite.config.ts` 提供隔离Dashboard，URL为 `/tests/bodyRadar/?bodyCapture=1`。API及Socket.IO仅连接本机5194测试服务，不能转发到现场。

另一个终端用后端虚拟环境启动 `python tests/bodyRadar/serve_fixture.py E:/code_product/gcms_src/flask_backend`，测试服务仅监听127.0.0.1:5194。不导入业务启动文件，不连接数据库或现场设备，geomcap发送器被替换为打印。页面右上角“模拟车身影像”用于加载四色原图，同时运行生产几何采集服务：先从本地HTTP读取3次空响应，再返回测试夹具的真实压缩LAZ，第6次响应带 `Capture-Finish: true`。轮询与车身图共用0.2秒间隔和结束判断，收到JSON也结束，正常结束及超时会调用被拦截的geomcap=false。

验证步骤：无采集时3D为空、截图禁用；启动后显示等待有效点云，自动切为3D并显示尺寸（切换视图即可看到，无须刷新），随后提示点云采集完成；模拟采集重置后回到默认车身图且点云清空，新一轮不能显示旧点云。截图步骤：加载车身图后点击截图，拖框后右侧出现裁块；勾选后追加到证据照，叉号只舍弃当前裁块；切换3D视图，旋转缩放后截图，拖框不能旋转模型，完成/取消后恢复旋转；反向框选、短按忽略、鼠标越界、取消及切换视图；检查平板缩放下坐标一致。业务页面已无演示标识或演示数据回退。

备注与证据回归：打开 `/tests/layout/index.html?bodyCapture=1`，点“模拟车身影像”“模拟原有证据和资料”，加载800×250预览和1600×500原图，预置2张证据照、1张货物照。框选并勾选后证据变3张；点“模拟临时图过期”令缓存超过2小时，已显示影像仍可框选；先叉掉一张（数量保持3张），再框选勾选（变4张）。打开提交确认，在备注中输入文字并确认。隔离服务使用生产提交接口及图片落盘逻辑，数据库仓库替换为验证器，照片仅写系统临时目录，核对后的备注、数量、尺寸记录到 `tests/layout/artifacts/crop-submission.json`，不会写业务数据库。

2026-11-10实测：原有2张保留，追加2张后共4张，货物仍1张；原图裁块512×298，缓存失效后的页面裁块246×165，全部成功写入隔离存储。备注随真实Dashboard提交请求传到后端。截图预览及确认后的证据持有data URL，不再随服务端临时缓存失效。
